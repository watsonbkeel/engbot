# v0.3.3 · 学生自定义场景专项改进

日期：2026-10-21。基于已交付 v0.3.2 的独立副本修改；原 ZIP 保留。没有部署或改动线上服务，没有使用真实学生凭证或模型账号。

## 从实际模拟发现的问题

四个虚构学生分别填写买午餐、寻找水杯、太空水箱谜题、自己当文具店员的描述。生成场景卡后，实际保存配置并通过公共服务、脑端、课程引擎和 SQLite 完成对话；GPT 在测试边界读取实际提示与历史，生成模型回复和学生话语。

1. 保存场景与开始场景练习之间缺少明确交接。完整练习会在词汇后使用场景，想直接进入场景还得自己发现模式选择。
2. 学生要求自己当店员、主动提问，生成与对话提示仍倾向机器人主导，并要求机器人每次追加问题或指令。
3. 实际任务已经完成，却必须凑满固定轮数。修改前文具店第3轮已交易并告别，程序直到第6轮才结束；失物招领也多说了三轮再见。
4. 模型只有最后一轮的 closing 标记，缺少可用于安排任务步骤的剩余轮数。
5. 自带模型请求总带供应商专用 thinking 参数，严格的标准接口可能因此拒绝有效配置。首轮场景接口替身没有覆盖这项兼容差异，后续依据官方协议与严格端点复现补齐。

## 代码改动

| 范围 | 修改与结果 |
|---|---|
| 场景与今日页 | 增加“保存并去安排练习”；保留“仅保存场景”。安排动作只先保存场景，再在同课堂今日草稿选中场景模式；其他未保存选项保留，最后由用户保存安排 |
| 页面交接 | 新增短期内存模块 scene-flow，绑定课堂身份和已保存场景内容；保存失败、隐藏页面、课堂切换、迟到回调和场景被替换不误激活 |
| 场景编辑 | 显示年级，复制实际年级，直接进入自己的 API 设置，并保留一次设置跳转期间的本课堂编辑草稿 |
| 场景生成 | 明确保留双方角色和学生指定的主导权；核心目标六轮内可完成，不为凑时长增加支线 |
| 动态对话 | 允许自然的纯回答；提供实际总轮数、已完成轮数和剩余轮数，避免机器人强制反问 |
| 自然结束 | 可选严格布尔值 scene_complete；配置场景、至少两轮学生交流且 relevant=true 时才可提前收尾。缺省兼容旧模型，上限仍为6/8/10 |
| 证据与点评 | 结束信号不增加单词掌握；保留最后一句、有效逐词证据和点评，不凭结束状态虚构目标完成 |
| 自带 API | 关闭深度推理且 HTTP400 明确拒绝整个 thinking 字段时，仅删除该字段重试一次；保持同目标、同凭证、TLS/SNI与原截止时间。开启偏好、其他字段或值错误不被吞掉 |

独立代码复核在可选参数识别器中发现一项 Important：消息前缀匹配会误把 thinking.type 或值错误当作整个字段不支持。新增失败回归后收紧为完整消息匹配并独立复验关闭。无未关闭 Critical/Important。

## 实际模拟结果

| 场景 | 修改前结课轮数 | 修改后结课轮数 | 修改后结果 |
|---|---:|---:|---|
| 三年级买午餐 | 6 | 5 | 短答、表达求助、问价、付款、拿餐和告别完整；求助不冒充独立表达 |
| 四年级当店员 | 6 | 3 | 学生主动问数量和袋子、报价、交付，机器人按顾客身份回答 |
| 五年级找水杯 | 8 | 3 | 描述和地点一致，see/saw 自然改述，确认认领后收尾 |
| 六年级太空任务 | 8 | 4 | 线索一致，学生能追问标签矛盾并报告送达；解释和点评全英文 |

这些是实际模拟的交流轮数，开场示范和求助不计入。前后重新生成的话语不是受控学习效果实验，不能把轮数变化解释为学习效率的统计提升。

完整对话见 [SCENE_SIMULATION_REPORT.html](SCENE_SIMULATION_REPORT.html)，逐次模型输入与输出在 `verification/scene-simulations/`。测试桥只在 tests 中，正式产品不会加载示例对话替学生回答。
