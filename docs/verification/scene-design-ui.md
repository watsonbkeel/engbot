# 学生自主设计场景：实际页面流程复核

日期：2026-10-21。基线：已交付 v0.3.2，Git `7feb890d6289d952b66f9159524c17937b6a0c34`。范围限定为学生自带模型、自己描述场景、AI 生成、检查编辑、保存、选用场景练习的流程。

## 验证方法与边界

阅读 `AGENTS.md`、`README.md`、`docs/DESIGN.md`、`docs/API.md`、`docs/TEST_REPORT.md`，跟踪真实 `settings`、`today`、`scenes` 的 Page JavaScript、WXML 和公共 API 包装。使用 `tests_js/helpers.cjs` 执行这些实际页面函数；只替代 wx 与 HTTP 边界，测试服务保存实际发送的配置正文。

没有调用真实模型，没有真实 API Key，没有使用微信开发者工具、手机、树莓派或儿童试课。以下结论是页面状态与导航契约的本地证据；不宣称微信渲染、模型教学质量或硬件语音体验通过。

## 已存在且可完成的能力

| 步骤 | 实际入口或行为 | 复核结论 |
|---|---|---|
| 填自己的模型 | 首次引导第 2 步；设置页的大模型区域 | 输入接口地址、模型名和 API Key，提交 `/api/llm`，成功后清空界面 Key，不把模型密钥写入本地课堂连接存储 |
| 找到场景编辑 | 今日练习 → 场景（可选）→ 当前场景 | 可以打开场景页，并把今日草稿的年级传入 |

`tests_js/scene-design-flow.test.js` 以 1、6、9 年级分别走自己的模型 → 自拟描述 → AI 生成 → 编辑开场白 → 保存 → 返回今日 → 明确选择场景对话 → 保存安排，并覆盖生成失败手填、保存失败保留编辑后重试。

修改前执行 `node --test --test-isolation=none tests_js/scene-design-flow.test.js`：**5 通过、0 失败、0 跳过**，退出码 0。它验证现有能力与错误恢复；由于测试明确执行了选择模式，不能据此声称现有学生流程已经足够清楚。本轮未重复运行已有 v0.3.2 的全部生命周期回归，统一门禁由主任务执行。

## 基线问题：保存后的选用步骤不明确

### 复现

1. 使用初始配置：grade=1、mode=full、scene=null。
2. 学生在设置页填写并保存自己的模型。
3. 今日练习把草稿年级改为 6，进入场景页。
4. 自己描述「火星温室里的园艺助手」，让 AI 生成，修改英文开场白后保存。
5. 此时服务端配置为 grade=1、mode=full、scene=刚保存场景。页面只提示「场景已保存，返回后可保存今日安排」。
6. 返回今日练习直接点击「保存安排」，服务端配置变成 grade=6、mode=full、scene=刚保存场景；不会自动变成 scene 模式。

### 原因与影响

`scenes.onSave()` 明确只提交 `{...cfg, scene:value}`。这一行为保留今日草稿不被场景保存顺便提交，是既有约定，本身不等于数据丢失。`today.loadSaved()` 也正确恢复年级、时长等未保存草稿，并合入已保存场景。

但面向「自己设计、接着进入该角色扮演」的学生，缺少明确的选用动作：场景页没有返回今日、选为场景对话的按钮，成功提示也没有提示「选择场景对话」。今日的场景入口只叫「当前场景」，且在创建后原本提示选模式的文字被换场景断点提醒替代。

需要准确区分：full 模式仍会在词汇环节之后使用场景；它不是完全忽略刚保存的场景。要下一轮直接进入角色对话，必须把 mode 设为 scene。引擎 `start()` 的初始阶段由 mode 决定，只有 scene 直接进入 dialog。故该项是学生流程的发现性与选用缺口，不能误报为完全没有自定义场景功能。

## 其他发现性缺口

- 场景页没有直接去设置自己的模型的入口，也不说明生成使用课堂已配置模型。模型尚未配好时，页面错误虽然可见，学生必须自己找到返回和设置入口。
- 使用的年级只在未就绪时有提示，就绪后不展示实际年级，学生难以确认生成条件。
- 场景页仍使用「孩子」而非学习者自己的口吻。模板先于自主描述，今日入口也没有直说「自己设计场景」。属于信息组织改进，不能称为后端生成能力缺失。

## 建议验收标准

1. 今日页面有明确的自主设计入口，场景页说明学生先写想法、AI 生成、检查修改、保存选用的次序。
2. 场景页能找到自己的模型设置，并看到本次生成所用年级。
3. 在保留草稿隔离与保存失败语义的前提下，提供明确的「用于场景对话」动作；其结果和下一步保存、唤醒提示一致。
4. 1、6、9 年级草稿继续传入生成；最终开课的年级、场景、模式与学生确认的安排一致。
5. 保留只保存场景而继续完整练习的选择；不能把未明确确认的其他草稿字段偷偷写入服务器。

最终修复与新验收结果应追加在本报告；本段为修改前观察，不代表修复后仍存在这些问题。

## 已实施的有限修复

保留原有「只写入 scene」的服务器契约，没有新增 API 字段、模式或配置版本，没有把今日草稿顺便保存。

1. 今日页入口改为「自己设计场景」，显示清晰的创建／修改按钮。场景页先给自主描述，再提供模板；角色与目标用「我」表达，并列出生成、检查、安排的步骤。
2. 场景页显示真实用于生成的年级，给出「填写 / 修改自己的 API」入口。该入口使用既有导航规则，不新增一次模型状态请求。跳到设置造成场景页关闭时，同一课堂的描述和编辑草稿只在内存中暂存一次；返回后可继续。未读到年级的草稿不会被恢复为默认一年级，换课堂不会带入别人的草稿。
3. 主操作「保存并去安排练习」先保存 scene，成功后返回今日页。今日先恢复原有年级、时长、词数、难度、中文辅助等草稿，再将 mode 选为 scene；显著提示「已选场景对话，请保存今日安排后开始练习」。只有学生再次点「保存安排」才提交这些选择。
4. 次操作「仅保存场景」保持原有行为，并说明完整练习会先练词汇，再使用场景。失败时草稿保留，不能导航或生成已选用提示。
5. 场景选用意图绑定课堂身份及已保存的五字段。旧页面晚到响应不能导航；换课堂或场景已被别的保存替换后，旧选用意图作废。课堂切换的失效检查在开始读取页面时执行，即使新课堂读取失败，旧选用意图也不能在切回后复活。正常从今日进入时返回原实例；直接进入场景或原生返回不可用时使用既有导航规则。即使新建今日实例，也从同身份的导航草稿恢复未确认选项。
6. 复制给外部 AI 的提示词带入当前已知年级，并替换服务端模板中的「当前 年级」。未读取年级时不编造年级。

内存草稿用于这次导航；它不提供关闭小程序后恢复草稿的承诺，也不存入模型密钥。练习仍由保存安排后对机器人说「小陈同学，学英语」开始，小程序没有假装远程启动语音课程。

## 修复验证

修改生产代码前，新增验收先得到 **5 通过、9 失败**：失败分别指向缺少选用动作、设置入口、年级复制和可见按钮。进一步用新建今日实例的返回、设置时年级尚未读取等具体路径检查，先复现 grade 6 草稿变 grade 1、未知年级被标记为已知等问题，再修正导航草稿传递。
