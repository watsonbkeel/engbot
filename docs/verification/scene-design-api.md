## 三个独立学生的完整路径

| 测试学生 | 年级、难度 | 学生的想法 | 机器人 / 学生角色 | Thinking | 实际完成轮数 |
|---|---|---|---|---|---|
| museum | 2 年级、basic | 参观化石馆，询问恐龙大小与食物 | 博物馆讲解员 / 小访客 | false | 6 |
| forest | 5 年级、standard | 护林员帮助迷路小狐狸找到树洞 | 迷路的小狐狸 / 护林员 | true | 8 |
| weather | 8 年级、challenge | 在学校气象站报告天气，决定户外观测安排 | 气象站值班老师 / 学生观测员 | true | 10 |

每人使用不同的 HTTPS 地址、模型 ID 和测试 Key。地址故意以 `/v1/chat/completions/` 结尾，以核对保存后的规范化以及运行时正确拼接。

每人均经过以下实际路径：

1. 家长凭证调用 `PUT /api/llm`。保存前请求包含真实课程 JSON 判题探针，成功后只返回掩码提示。
2. 调用 `POST /api/scene/generate`。模型收到该学生的描述和年级；生成草稿没有自动覆盖已保存的学习配置。
3. 对返回场景的 `goal` 追加学生选择，并调用 `PUT /api/config` 保存。重新构建 `Store` 后能读到完全一致的五字段对象。
4. 创建该学生的实际 `PublicClient` 和脑端，通过 `/voice/turn` 开始。首先返回指定英文开场白；开场完成后进入角色交流。
5. 完成 basic / standard / challenge 对应的 6 / 8 / 10 轮，最后保留角色回复，生成点评，并以 `active=false, phase=done` 收尾。
6. 保存探针、场景生成、角色对话与结束点评的全部供应商请求，都使用该学生自己的地址、模型、Key 和 thinking 设置；未意外调用平台模型。

## 设置传播、身份与密钥

| 核对点 | 实际断言 |
|---|---|
| 接口地址 | 自带服务请求使用规范化后的 `/v1/chat/completions`；测试传输看见固定 IP，原主机名保留在 Host 与 TLS SNI 扩展中 |
| 模型与 thinking | 每次实际供应商请求的 `model` 与保存值一致；`thinking.type` 分别为 enabled / disabled |
| JSON 请求格式 | 保存探针、生成、对话与点评均带 `response_format={"type":"json_object"}` |
| 角色和目标 | 每轮对话与点评的 user JSON 均携带编辑保存后的完整 scene；学生 goal 没有被拼接为 system 指令 |
| 密钥返回面 | 保存响应、GET 设置、脑端响应及 Tutor 快照均不含完整供应商 Key；GET 只含 `key_hint` |
| 脑端边界 | 实际 `PublicClient` 请求使用学生 brain 课堂凭证；请求正文不含供应商 Key |
| 跨学生隔离 | forest 的家长凭证不能读取或修改 museum 的模型，也不能为 museum 生成场景 |
| 角色隔离 | brain 凭证不能调用家长专用的模型读写或场景生成接口 |
| 同地址更新 | 规范化后同一地址可复用已保存 Key，更换模型和 thinking |
| 更换地址 | 未提供新 Key 时返回 422，未向新地址发送旧 Key，原设置保留 |

这里验证的是接口输出与状态对象中的密钥边界。小程序第一次由用户输入 Key 并提交保存是授权的数据流；这些后端测试不替代实际手机端或浏览器内存的检查。

## 错误与恢复

| 情况 | 观测结果 |
|---|---|
| 替换模型返回普通文字、JSON 数组、`correct` 字符串或错误键名 | 422，明确“未保存”，之前有效的整条模型设置不变 |
| 替换模型输出被截断，或供应商返回 401 | 422，原模型与 Key 保留；保存测试不借平台模型掩盖失败 |
| 生成对象的角色或目标为空、开场白为中文、字段超长、出现额外字段 | 422，明确格式错误，之前学习配置不变 |
| 自带模型返回非 JSON 对象或供应商 HTTP 503，平台可用 | 先请求学生模型，再使用平台模型；学生设置记录 `fallback` 与错误原因 |
| 回退到平台 | 平台请求使用平台自身的 Key 和模型，未带学生 Key |
| 无自带模型且无平台 Key | 503；没有外部请求，没有虚构场景 |
| 平台未配置、学生自带模型有效 | 保存和场景生成均成功，证明自带模型工作不依赖平台 Key |
| 学生自带模型 401 且平台未配置 | 503；设置状态保留自带模型的密钥错误，无场景自动保存或假成功 |
| 角色对话为 JSON 对象但 `reply` 不合格 | 脑端 503，保留原开场题位与场景，不更新进度 |
| 上述对话恢复后重试同一请求 | 重新获取有效回复，正常进入对话；随后相同编号回放首次成功结果，不额外调用模型 |

有效 JSON 对象的具体语义格式由相应调用者校验：例如缺少正确 scene 字段会返回 422，缺少正确 dialogue 字段会由脑端拒绝。此时并不自动把“对象格式有误”当成传输失败去平台重试，与当前 API 文档一致。

如果自带模型失败且平台没有 Key，生成接口的最终 503 会提及平台未配置；自带模型的具体失败原因可在 `GET /api/llm` 的 `last_error` 查看。本次只记录该现有错误路径，没有改动其文案或宣称平台缺失导致有效的自带模型不可用。
