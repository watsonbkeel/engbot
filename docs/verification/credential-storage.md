## 2. 存储约定

`Store(path, dictionary, timezone='Asia/Shanghai', credential_key_path=None)` 使用以下优先顺序确定主密钥文件：显式 `credential_key_path`、环境变量 `LLM_SECRET_KEY_FILE`、`Path(str(DATABASE_PATH) + '.key')`。默认示例为 `/var/lib/english-class/class.sqlite3.key`。

主密钥是 `cryptography.fernet.Fernet` 生成的随机密钥，独立文件权限 0600。新文件先在同目录私有临时文件中写完并 fsync，再通过不覆盖目标的原子链接发布；不会用新随机密钥覆盖已有文件。已存在且权限正确的密钥只读打开，因此可以放在 systemd `ProtectSystem=strict` 允许读取、禁止写入的位置。放入这类目录前，管理员必须准备好原文件与 0600 权限，服务不能代为在只读目录创建它。

SQLite 的 `api_key` 字段现在保存 `enc:v1:` 开头的 Fernet 密文。加密载荷同时绑定学生 ID；将一个学生的密文复制给另一个学生不能通过解密。公共服务按需解密后向对应模型发送；GET `/api/llm` 仍只给掩码提示，主密钥与原始供应商 Key 不进入脑端、Pi、导出的学生目录或小程序。

缺少或损坏主密钥会阻止打开已迁移数据库；存在已保存模型密文时，不匹配主密钥和损坏密文也会明确失败。它们不会被当成明文重新加密，也不会触发新主密钥覆盖。已清除全部学生模型设置时，已迁移库仍要求主密钥文件存在并且格式有效，但没有剩余密文能验证它是否为历史原Key；因此管理员仍须保留原文件并让备份配套，不能把这一边界视为主密钥轮换功能。

新建的数据目录逐层用 0700；已有父目录保持原权限，避免改坏共享目录。数据库、已有 WAL／SHM／journal、迁移锁文件和主密钥收紧为 0600；后续 SQLite 辅助文件继承私有数据库模式。最终路径为符号链接或非普通文件时不会作为密钥或数据库使用。应用不会把主密钥内容或解密结果打印到日志。

对已有 SQLite 主文件及辅助文件，权限检查只用 `lstat`／不跟随符号链接的 `chmod`，不会另外打开再关闭这些文件。这一点保护同进程其他 SQLite 连接已经取得的 POSIX 记录锁；独立审查真实复现了先前“只为收紧权限而打开／关闭文件”会使另一进程错误进入未提交事务的问题。该实现已修复，并由真实子进程写事务回归覆盖。

## 3. 首次升级与可恢复迁移

升级前先结束课程，停止公共服务以及其他会打开同一数据库的旧版 CLI、备份读取任务或检查工具。保留可信、访问受限的升级前备份；它仍可能含明文，应按凭证材料保管。新版本不能代替管理员清除旧备份。

迁移由 `english_class/migrations.py` 管理。进程间文件锁使用独立的 `DATABASE_PATH + '.migration.lock'` 文件，覆盖整个初始化及清理窗口；不用数据库本体充当文件锁。表结构操作和版本登记位于 `BEGIN IMMEDIATE` 事务中。没有引入数据库迁移框架。迁移锁文件应保留在数据库旁，不要在进程仍运行时删除或替换它。

| `schema_migrations.version` | 含义 |
|---|---|
| 1 | 创建或补齐原有表、thinking、学习证据与心跳字段；保留原有学生、角色凭证、配置和进度。 |
| 2 | 增加 `allow_platform_fallback`，旧行默认 false；增加 `success_count`，旧行默认0；验证已有密文并将旧明文 Key 加密。 |
| 3 | 明文迁移后的数据库空闲页重建和 WAL 清理完成。 |

连接启用 `PRAGMA secure_delete=ON`。版本2提交后，执行 `VACUUM` 重建旧数据库空闲页，再执行 `wal_checkpoint(TRUNCATE)`，检查没有繁忙状态或遗留 WAL 帧，才登记版本3。该过程需要足够的临时磁盘空间。旧读事务导致检查点无法清理时，启动明确失败，保留已经加密的数据与原主密钥；关闭旧连接并重启会继续完成清理，而不是重复加密或遗失身份。

测试检查的是可访问的 SQLite 主文件与辅助文件中不再出现指定的虚构密钥字节。它不是对 SSD、文件系统快照、复制写存储、旧备份或已外传文件的物理擦除保证。已泄露的供应商 Key 仍需在供应商控制台撤销。

### 备份、恢复和变更主密钥路径

- 数据库用 SQLite backup API 获取一致副本；不要只复制正在写入的主文件而漏掉 WAL。
- 主密钥另行备份，保留 0600 和受控所有者；与数据库备份分别存放。默认同目录只是运行时位置，不应把整个目录原样作为“只有加密数据库”的对外材料。
- 恢复时必须同时恢复匹配的数据库和原主密钥，并让公共服务以及创建学生的 CLI 使用同一个 `LLM_SECRET_KEY_FILE`。本版没有主密钥在线轮换入口。
- 将主密钥改放其他路径时，先停止公共服务，原样复制当前主密钥，设置新路径和权限，再验证启动；不要生成新随机文件。受 `ProtectSystem=strict` 保护的 `/etc` 等目录应由管理员提前准备，所有者可设为 `english-public:english-public`、模式0600，目录也应限制可访问用户。
- 单独遗失主密钥无法从密文恢复供应商 Key。保留故障数据库和现有文件，先找匹配备份，不要删除文件试图“自动修复”。
- v0.3.3 代码不能读取 v0.3.4 加密后的供应商 Key。回退代码时需要匹配的升级前数据库备份，不能只回退程序后继续使用已迁移库；旧备份仍含敏感凭证且不包含升级后的新记录，恢复前应评估这些记录的保留要求。

`install_server.sh` 初始化和 `create_student.sh` 创建学生都向 CLI 传入同一份 `/etc/english-class/public.env`，直接使用其中的数据库、词库和主密钥路径，不再用脚本固定路径覆盖自定义数据库。手工运行可用 `python -m english_class.cli --env /etc/english-class/public.env init`；该参数复用服务端的安全 KEY=VALUE 解析器，不执行 shell 表达式。显式 `--database`／`--dictionary` 优先于文件中的路径，因此同时指定时应确保它们确实对应同一课堂。

家长更换供应商 Key 仍通过原有 PUT 测试成功后保存，验证失败保留旧值；DELETE 删除当前学生的保存设置，并选择平台模式。它们只管理本服务的副本，不会替家长调用供应商撤销权限。旧版备份中的原 Key 不会因当前库删除而失效。

## 4. 尝试与成功计数

`reserve_scene_generation(student_id, limit=20)` 在事务内占用一次尝试并返回所属 day，防止并发绕过每日上限。失败、超时、供应商拒绝或输出不合格仍占一次尝试。拒绝的第21次不再调用模型，返回的中文明确包含“已请求”和“包含失败尝试”。

只有完整场景通过五字段验证后才调用 `mark_scene_generation_success(student_id, day)`。`scene_generation_usage(student_id, limit=20)` 返回 `{day, attempts, successes, limit, remaining, successes_since_version:'0.3.4'}`。这里不返回 `failures=attempts-successes`，因为请求可能尚在进行，升级前也没有可靠成功计数。

旧版的尝试数完整保留，成功数从升级后开始累计，不能把旧尝试解释为全部失败。跨午夜返回的成功归属最初预留的日期；数据库暂留昨天的数据，避免午夜后新请求清理掉仍在途的昨天请求。失败没有退款；成功计数不改变原有20次尝试的防滥用上限。

## 5. 自动化证据

专项测试：`tests/test_credential_storage.py`。先在 v0.3.3 基线看到15项预期失败，再实现修复；随后补充了外部只读主密钥、跨学生密文绑定和进程间写事务互斥检查。测试覆盖真实文件与 SQLite 的持久化、权限、缺失／错误主密钥、损坏密文、旧库身份和配额保留、旧读连接阻塞清理后的恢复、并发启动、替换与删除、并发尝试上限以及午夜归属。

独立审查发现的 POSIX 锁问题对应 `test_file_security_operations_do_not_release_active_sqlite_transaction_locks` 的2种参数：主进程持有未提交写事务，子进程尝试 `BEGIN IMMEDIATE`；权限收紧和迁移文件锁操作前后，子进程均必须无法写入。两种参数分别在旧实现中真实失败，改为不打开已有 SQLite 文件、迁移改用独立锁文件后通过；权限用例实际将数据库及辅助文件从0644收紧到0600，覆盖真实操作而非仅检查不变的权限。

`tests/test_credential_cli.py` 的3项测试先复现 CLI 与部署脚本不读取独立主密钥路径，再通过真实 CLI 验证修复。独立审查随后发现的固定数据库参数覆盖环境配置问题，也先由2项真实脚本命令测试复现，再移除覆盖参数；自定义库保留已有学生的加密 Key，并接收新学生，固定默认库不被创建。脚本测试只替换部署路径和切换系统用户的边界，执行两个脚本中实际的 CLI 命令；没有执行 apt、创建系统账号或启动服务。包含带空格的主密钥路径和环境文件中的 shell 文本不被执行。存储与 CLI 专项共22项通过，连同原工具与旧库迁移回归共47项通过；这不是全套门禁结果，全套结果由本版统一报告记录。

外部主密钥只读测试模拟 systemd 文件打开权限边界，并使用真实 Fernet 与 SQLite；没有在目标云主机运行 systemd 权限矩阵。其他存储测试使用本地临时文件，完整供应商与前端政策回归由本版统一测试报告记录。

```bash
python -m pytest -q tests/test_credential_storage.py
```

实际目标环境还须核对服务用户、恢复目录权限、主密钥独立备份、磁盘空间，以及公共服务和 CLI 使用相同的主密钥路径。上述本地证据不代表线上配置已经完成。
