## 已修复的学习行为

### 1. 四种模式与配置生效

`full` 保留听词理解 → 主动回忆 → 必要时跟读 → 简易对话；有场景配置时最后一段改为角色扮演。`en2zh` 只做听词理解，`zh2en` 从回忆开始并在词表结束时收课，`scene` 直接练场景。强行保存 `scene` 而没有场景配置时，回退到原单词对话。新开始仍重新读取配置和历史进度，配置变化使旧词汇断点失效。

`zh2en` 和 `scene` 单独练习时，正确、实际使用目标词、未借助示范的独立表达可直接达到状态 2；否则没有听辨阶段的新词永远无法完成该模式目标。`full` 继续保留“先有听懂记录”的前置要求。全部模式都保留历史最高状态，不把这次错误、跟读或没听清降级为历史不会。

### 2. 求助可以回到原题（L1）

`听不懂 / 什么意思 / 这是什么意思 / 这个词什么意思 / 给我提示 / 用中文解释` 对应 `explain`。旧 `help` 动作兼容为 `explain`。解释保留当前阶段、索引、对话轮数，不写“已掌握”记录，不跳过题目。

`我不会 / 我不会说 / 怎么说 / 不会说` 对应 `howtosay`，流程为：收集中文意图 → 中文确认与英文表达 → 跟读 → 回到原题。主 `phase`、`index`、`dialog_count` 不被求助推进。听不清、重复、暂停/继续及恢复快照保留正在等待的语言和求助阶段。在跟读阶段再次要求解释，会解释并重播正在跟读的表达，不会把题面退回后却仍等待另一个答案。

中文辅助关闭时，`howtosay` 只说 `Try one word first.`，不进入中文轮；`explain` 使用更简单英文。英文线索、对话和点评的模型输出若出现中文，会被拒绝或以英文结束提示处理，不作为合格结果播报。

**模型依赖的明确取舍：**词库已有的当前词义解释、中文词义精确匹配到该词的表达帮助可以本地完成；任意中文意图翻译、上下文改述、自由对话和场景点评需要真实模型。缺少模型时返回明确服务错误，绝不伪造翻译或偷偷切测试替身。这解决了 v3 中“任意表达帮助”与“不依赖 LLM”之间的实际冲突。

### 3. 证据与计数诚实（L3、L4、L5、L9）

每次对话只调用一次结构化 LLM，返回 `word_evidence`，按原始 `word_id` 给出布尔 `correct` 与 `independent`。每个被说到的词分别核对；全句 `relevant` 不再用于替代逐词正确性。未知 ID、重复 ID、错误类型等证据不参与升级。缺少某词合法证据时不提升它，并返回本回合 `evidence_incomplete=true`；正常角色回复保留，孩子可以继续练习，不把模型证据不完整误报为孩子答错。该标志随快照保存，但新回合重置。

直接复述二选一中的词、完整照抄上一句、明确给出的示范或帮助跟读都不成为独立掌握。普通问题含目标词，不自动把孩子的所有回答都判模仿；原回归仍确认 `Do you like apples?` 后有意义的完整回答可以获得独立证据。

`assisted_words` 表示当前任务受过帮助，保守阻止立即升级；`assisted_models` 只表示实际被示范过的词。这一区分防止“帮助说 apple，孩子另说 banana”时错误累加 banana 的模仿次数。

计数规则为：

| 观察 | `answer_valid` | `used_word` | `imitated` | 掌握状态 |
|---|---|---|---|---|
| 无提示听懂并给对词义 | true | false | false | 至少 1 |
| 独立且有效使用目标词 | true | true | false | 条件满足时 2 |
| 说到了词但该词语义错误/证据缺失 | false | true | false | 不提升 |
| 实际成功跟读/直接回声 | false | false | true | 不提升 |
| 两次普通跟读都没说出目标词 | false | false | false | 不提升 |
| 没听清 | 沿用 unclear 记录 | 不加 | 不加 | 不降级、不推进 |

`used_word` 仍表示可从文本观察到“说出了目标词”，不等于正确理解或独立掌握；跟读按 v3 单独计数。停止后续学也保留本题已受帮助/已示范的事实，避免退出再进入就把即时回声重新标成独立回答。失败跟读的口头反馈改为“还要练”，不再说已完成。

### 4. 场景与结束连贯（L2、L6）

开场提示本地生成，等待配置的英文开场白；大小写、标点和多余空格不影响匹配。第一次失败重示范，第二次失败慢速示范后进入角色对话，开场跟读不计独立掌握。

场景难度分别为 6/8/10 个已听清并成功处理的回答回合，无论回答正确与否；开场、求助、没听清不耗用对话轮数。场景不按分钟超时。`I want to stop` 与中文结束都能退出。到上限时，模型收到 `closing=true`，要求自然回应并纠正最后一句、不再提新问题；这份最后回复先被保留，然后播报有依据的肯定、至多三条建议，最后结束。场景少于两句学生发言时不给改进清单。点评服务失败或输出不合法时，明确告知点评不可用并结束，不困住学生、不编造点评。

角色、目标、开场白和学生设计偏好在用户 JSON 数据中传递，不拼进系统指令。原 `scenes.md` 所有 ID 均保留；新增 `tutor_explain` 与 `tutor_howtosay`。开场模板使用 `{scene_name}`，避免与固定接口 `render_prompt(name, **values)` 的参数重名；对外 `SceneConfig.name` 未改变。三个原模板的角色字段已缩短至 40 字符以内。

### 5. 语速与可靠性接口（L7、L8，以及 E02 配合）

每次结果返回 `speed=elementary/middle/high`，由年级计算（1–6、7–9、10–12）；实际 TTS 速率和慢速叠加由语音任务实现。这里没有宣称听感或响应时延已达标。

`export_state()` 返回版本化 JSON 快照，集合显式编码；`restore_state()` 重建集合、删除快照之后临时生成的运行字段，并对学习计时、静默计时与暂停计时做单调时钟重基准，避免把停机时间算进本次学习。`io/clock/wall/state_path/defer_resume_changes` 属于外部依赖，不被恢复数据替换。

`defer_resume_changes=True` 时，词汇断点的保存/删除变成快照内的待执行操作；脑端持久化回合和回复后才调用 `commit_resume_changes()`。进入对话先成功生成下一题，再排队删除断点；失败转移不删除可用断点。部分写入重放、丢回复重试和问题身份由工程任务的脑端回合日志负责。音频测试已改为每道题先取得当前 `session_id/question_id` 再提交，防止把两段旧题录音串到不同题。

## 尚需真实设备/模型验收

这组测试证明状态、字段、错误分支和记录约束，不证明真实模型会持续给出正确的逐词判定或自然纠错，也不证明 ASR 准确率、发音表现、语速听感与 ≤8 秒时延。

- 用正式词库的首次范围（开头 hello / hi / I 等）和至少一组实际年级词，确认题目与场景难度匹配；apple/banana 替身只隔离测试算法。
- 每个学段做一次完整真实语音练习，听词、回忆、两种求助、暂停/继续、场景退出都用口语触发；确认学生停顿不会被切成下一题答案。
- 同一目标词依次做“只听懂、跟读、二选一照抄、独立新句”，检查实际记录与上述证据表一致；构造一句整体相关但含另一个错误词义的回答检查逐词判定。
- 关闭中文辅助后检查开场、提示、两种帮助、角色回复与结束点评，不能混入中文；逐档试听语速。
- 场景抽查至少五轮角色连贯性，末轮故意说错误句型，确认听见自然纠错后才收课；点评不超过三条，不评价文本无法支持的发音。
- 无推理模式下实测五轮说完到开口的平均时延，并另外记录尾部最慢回合；网络丢回复和进程重启验证由工程任务联调报告覆盖。

学习侧没有已知未修复的状态机阻断问题；真实模型语义质量、课堂适龄程度、麦克风/ASR 与实际播音时延仍需要上述现场证据。
