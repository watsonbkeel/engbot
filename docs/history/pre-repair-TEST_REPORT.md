## 覆盖的具体行为

跨学生凭证拒绝；家长不能写进度或调用模型；配置范围与字段检查；未知单词拒绝；进度只升不降；重复请求不重复计数；词库内容作为数据解析、不执行JavaScript；无破坏小程序合并；学生导出配置不包含真实供应商凭证。

完整词汇听说流程；下次读取新配置；帮助跟读不计独立会说；没听清保留原题、示范上下文与状态；中文辅助关闭；暂停／结束／时长上限；并发录音按正确题目语言串行处理；过长请求编号转为固定摘要；模型错误不使用假回答。

实际以127.0.0.1 HTTP运行测试供应商、公共服务和学生脑端：经过模型请求序列化、ASR上传、TTS WAV转换、ffmpeg解码、SQLite保存、家长查询和配置切换。**供应商端在测试中使用明确标记的替身；测试音频是用于格式验证的合成数据，不是儿童声音。**

小程序实际页面逻辑在Node的wx/Page测试环境中执行：加载表单、提交真实约定字段、失败不提示保存成功、报告区分空记录与网络错误。它不是微信开发者工具或真机渲染测试。

## 自查发现并修复

1. “没听清”反馈不能覆盖原题，否则重复指令会重复错内容；同时保留上一轮示范，避免跟读误升级。
2. 长request_id不能让进度请求超过头字段长度；改为固定SHA-256摘要。
3. 两个音频请求不能先分别识别、再错位推进；识别和状态推进纳入同一串行操作。
4. 导出目录不可写时不能先产生无法取回凭证的学生记录；文件准备成功后再提交学生。
5. 声卡播放进程失败不能静默当作播报完成；增加可辨认错误，并提示重播当前题目。

这些修复均先通过回归测试观察到失败，再修复并运行完整测试。代码自查在当前开发会话内完成，没有声称已由独立团队审计。

## 第二轮评审修复（2026-10-01）

全套：Python **120通过**、Node **16通过**。新增回归：
- 语音门限：100毫秒短词（前300毫秒+尾1秒静音，即树莓派实际切法）、轻声、整句、长尾静音须送识别；纯静音、20毫秒咔哒声、持续白噪声（两种强度）拦截。旧算法取整段90分位音量，短词会被当静音拦掉。
- 识别总超时：模拟分块慢速返回（每块都在读超时内），0.25秒上限须在0.4秒内结束并降级，原因为Timeout。
- 腾讯云畸形响应：Result为数字/布尔/缺失/null，Error为字符串或Code非字符串，Response非对象——全部按协议错误降级，不算没听清。
- 降级诊断：结果保留错误码和RequestId；日志含backend/provider/fallback/code/request_id/ms，不含密钥、签名、音频base64。
- 词形：be不匹配bed、I不匹配is、see不匹配seed、hop不匹配hoping；is/were/saw/hopped/used等仍匹配。用正式词库4115个单词对比新旧规则：去掉的变形全部是误匹配（bed/is/its/riding/noted/seed等），没有丢掉真实变形。
- 英文线索含答案变形（apples）即拒绝；回忆判对但未说出目标词不升级；对话阶段没听清不让树莓派丢弃排队中的回答，进入下一轮才丢弃。
