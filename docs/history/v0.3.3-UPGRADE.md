# 升级到 v0.3.3

本包不会自动更新线上服务。v0.3.2 → v0.3.3 保留现有 SQLite 表结构、角色凭证、配置字段和 `voice_protocol=2`；需一起更新公共服务、各学生脑端、Pi 和小程序，才能获得全部修复。更早版本的服务拆分与首次迁移说明保存在 [history/v0.3.1-UPGRADE.md](history/v0.3.1-UPGRADE.md)，目标版本仍以本包 v0.3.3 为准。

## 1. 本次升级影响

本次专门修复学生自定义场景流程：明确保存后去安排练习的入口，保留角色和学生提问权，向模型提供剩余轮数，并允许实际任务自然完成后提前点评。场景的 6/8/10 轮改为上限。`scene_complete` 仅为模型的内部可选严格布尔值，缺省兼容旧行为；它不代表掌握、不增加数据库字段，不改变 voice_protocol=2。

自带 API 兼容增加一次严格受限的可选参数重试：关闭深度推理时，只有明确不支持整个 `thinking` 字段的 HTTP 400 才移除该字段；仍保留原目标、凭证、TLS 校验和总时限。支持该字段的供应商行为不变；开启但不被支持时明确报错，不静默改变设置。

v0.3.2 的修复持续保留，前版升级报告见 [history/v0.3.2-UPGRADE.md](history/v0.3.2-UPGRADE.md)。下列网络、证据及恢复约束仍适用。

| 变化 | 需要了解的行为 |
|---|---|
| 自带模型固定公网 IP 连接 | 必须能从公共服务直连公网 HTTPS；不用环境代理。原域名的 Host、TLS SNI、证书主机名验证保留。老师配置的平台模型维持原网络行为 |
| 录音格式错误 | 当前题位的不合格 WAV 返回 422，Pi 提示重新回答；不再进入无休止的未确认回合重试 |
| 成功跟读记录更严格 | 猜词列表、示范后的错误使用不增加成功跟读。旧版已有累计次数保留，不凭不足的历史证据重算 |
| 记录文案 | “曾听懂／曾独立说出”表示历史最高达成；今日词条上的次数仍是累计，不能当作今天的成绩 |
| 对话与点评上下文 | 新增本轮求助标记、最多 10 个词的最新事实，无新数据库评分、无额外模型调用、无新帮助原文档案 |
| 场景生成 | 从今日页进入时采用未保存的年级草稿，但不会擅自提交今日配置；直接进入时先读取已保存年级 |
| 模板 | “文具店”“午餐点餐”在前，原三个兴趣场景仍保留 |

自带模型如果此前依赖 `HTTP_PROXY`／`HTTPS_PROXY`，升级后可能无法直连。先确认可直连的地址，或由老师评估后配置为平台模型。不要用关闭证书校验来绕过错误。保存自带模型时仍会进行真实 JSON 格式验证，验证失败不会覆盖原配置。

## 2. 结束练习并备份

选择没有孩子正在练习的时间，明确结束当前课程。备份代码、学生自定义 prompts、服务单元、`/etc/english-class`、Pi 插件配置、脑端和 Pi 状态目录。凭证备份只放在老师控制的位置。

SQLite 使用 backup API，避免单独复制仍在写入的主文件而遗漏 WAL：

```bash
sudo /opt/english-class/.venv/bin/python - <<'PYBACKUP'
import sqlite3, datetime, os
path='/root/english-class-before-v033-'+datetime.datetime.now().strftime('%Y%m%d-%H%M%S')+'.sqlite3'
with sqlite3.connect('/var/lib/english-class/class.sqlite3') as source, sqlite3.connect(path) as target:
    source.backup(target)
os.chmod(path,0o600)
print(path)
PYBACKUP
```

不要重建已有学生、替换成测试数据库或删除旧进度。

## 3. 在新目录验证，然后合并代码

解压本包，在新目录安装开发依赖并运行：

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements-dev.txt
PATH="$PWD/.venv/bin:$PATH" bash scripts/test_all.sh
```

这一步不需要真实模型密钥，不改生产数据。包内结果见 [TEST_REPORT.md](TEST_REPORT.md)。

只暂停本项目的 `english-public` 和需升级的 `english-brain@学生ID`。保留现有虚拟环境、配置、数据库和凭证，合并本包代码和文档，按 requirements 安装依赖。

**各学生脑端运行自己的代码副本。** 公共目录更新不会自动覆盖 `/opt/english-class/students/<sid>/english_class`。合并完整 `english_class/`、`prompts/scenes.md` 和 `prompts/student.md` 的教学变化；保留学生已有个性化设计，不盲目覆盖。不要只复制 engine.py。

v0.3.1 / v0.3.2 的 SQLite 升级到本版不需要额外迁移。v0.3.2 为旧课堂快照和续学断点补充新上下文默认值，回滚失败回合时不会保留新生成的错误状态。已经完成并缓存的旧回合仍回放原结果，避免重新判题或重复记次；它们不被回溯应用新教学判断。

若升级时恰有旧版本（包括 v0.3.1 / v0.3.2）未确认回合，新版不会在改变后的提示词下重新判题。Pi 重试原请求时，先用旧日志中的原载荷和幂等键确认尚未确认的学习写入；已确认写入不再发送。成功后返回明确的“系统已升级，本轮练习已结束，已确认的学习记录已保留，请重新开始”，原请求可安全重放，旧续学断点清理后才能新开课。确认服务暂时失败则保留原请求供重试。

这是明确收尾，不是未完成场景的无缝续答，也不代表整节课的全部目标已达成。孩子明确停止时可直接退出，不等待故障服务；尚未确认的意图可被放弃，已写入数据库的记录保留。没有未确认回合的旧课堂快照仍可正常迁移继续，已完成缓存回复仍按原结果返回。

## 4. Pi 与小程序配套更新

Pi 合并本包 `pi/` 与其引用的共享 `english_class/` 模块，保留本人 `pi.env`、ALSA 配置和模型。v0.3.1 既有私有状态目录继续使用。若从更早版本升级，需安装配套服务单元并 `systemctl daemon-reload`，不能只换源码。

微信开发者工具导入包内 `小程序-english-helper/`，或使用主工程 `miniprogram/`；两者同源。保留自己的 AppID 与本人连接，清理旧编译缓存后重新构建。正式后台配置 request 和 downloadFile 合法域名。

## 5. 恢复并验收

先启公共服务，确认 `/health` 的 `version=0.3.3`，再启学生脑端和 Pi。核对旧进度仍在，做一轮短文字练习，然后按 [INSTALL.md](INSTALL.md) 第 8 节做真实语音和手机验收。

本次重点确认：

1. 自带模型保存验证和真实对话可用，网络不依赖已被禁用的环境代理路径。
2. 解释、表达帮助、跟读、回原任务均可完成；示范后的回答不冒充独立表达。
3. 自己描述场景并生成，点击“保存并去安排练习”，确认今日页选中场景模式且保留草稿，再保存安排；下一次开课进入正确角色。
4. 试一次学生当店员、机器人当顾客的场景；学生能提问，交易完成并告别后直接进入点评，不再反复说再见。
5. 听力换年级期间旧列表消失，无法误播旧年级；加载完成后可正常播放。
6. 结果页的历史达成、累计次数与空记录说明清楚，原记录保留。

脑端回合恢复和 Pi 未确认请求最长保留 6 小时；词汇续学断点保留 7 天。本次新增上下文不改变这些期限，不提供永久儿童对话档案。真实供应商、ASR、Pi 耳麦、微信真机和端到端延迟仍需目标环境验收。

## 6. 回滚

若升级后的目标环境存在阻断，停止本项目相关服务，保留当前数据和错误证据，再恢复匹配版本的代码与配置。v0.3.2 → v0.3.3 没有数据库结构变更，通常无需恢复旧数据库；先保留升级期间的新记录。新短期状态由对应版本管理，必要时在已明确结束练习后从备份恢复，不任意删除正在使用的数据。

从更早版本升级的回滚还须匹配其配置和数据库合同。恢复旧数据库会丢失备份后的新记录，不应自动执行。原 aibot 的麦克风服务切换仍只通过 `course_mode.py on/off`；升级公共层无需停止原机器人。
