## F032-1：旧未确认回合不能只迁移 Tutor 字段

**位置：** `english_class/turn_recovery.py` 的 `TurnRecovery.begin/invoke/complete/settle_records`；`english_class/brain_api.py` 的 `run_turn_locked/close_upgraded_turn`；`Tutor.restore_state`。

**独立复现：** 从真实 v0.3.1 Git 基线加载旧 Tutor，配合实际 SQLite 和回合日志运行 full、1 个词 apple。先完成听辨；回忆答 apple，正确证据已写入数据库，再让下一句对话生成失败。磁盘中未确认操作依次为 `chat(done=true)`、`record(done=true)`、`chat(done=false)`。重建 v0.3.2 Tutor 并恢复该日志，用原 request_id/回答重试：前两个操作重放成功，到新对话调用时因系统提示及 support/observations JSON 改变，IO fingerprint 不同，抛出：

```text
ServiceError: 恢复回合与当前程序状态不一致；请结束练习后重新开始
pending = true
```

判题计数仍为 2，apple 的 used_word_count 仍为 1，没有重复记分，但原请求不能完成、Pi 持续处于未确认恢复等待。单独为旧快照补 task_helped 和 lesson_observations 默认值，无法解决跨版本操作序列合同变化。

**影响：** 服务更新恰逢失败/丢失回复时，正常恢复无法完成当前请求。直接放松 fingerprint、在新提示下重新判题，或删除旧日志，会损害原写入的稳定性，不能作为修复。

**最终修复：** 新 pending 记录 executor_version；无版本或异版 pending 进入明确的升级结束流程。原编号、原内容重试时，仅逐条确认未 done 的原 record，保持其 args、kwargs、幂等键，每条确认结果原子落盘；已 done 的写入不再发送，不调用模型或 ASR。确认失败保留剩余 pending。明确停止允许放弃尚未确认意图，不等待不可达的公共写入，已提交记录保留。

完成时返回“系统已升级，本轮练习已结束，已确认的学习记录已保留，请重新开始”，不是声称整节课已经学完。原请求回复和显式停止回复按各自编号一次原子保存，使用共同的新题号；缓存成功后才清除续学断点和活动历史。旧损坏 WAV 的升级收尾先于新 WAV 校验，因此旧版已经留下的无效录音 pending 也能解除。没有 pending 的旧状态正常迁移继续，已经完成的旧缓存保持原回复。

**追加独立复现与修正：** 首轮收尾实现遇到 resume 删除失败时，只阻止显式 action=start。实际发送默认 answer、text=“开始今天的英语练习”，仍返回 200、phase=recall、active=true，把旧断点重新加载。该问题已修复：脑端按与 Tutor 相同的可靠文字控制规则计算 effective_action，仅用于门禁，原 body 和 fingerprint 不变；文字 API 与旧 `/voice/push` 都受同一开始/停止保护。低置信度和 unclear 不触发控制。

**独立最终复验：** `tests/test_v032_upgrade.py` **11 passed**。其自包含夹具 `tests/fixtures/v031_pending_turn.json` 来自真实 v0.3.1 brain、Tutor 和 TurnRecovery，不要求交付 ZIP 包含 Git 历史。覆盖如下：

| 边界 | 实际断言 |
|---|---|
| 旧写入已提交但回复丢失 | 原键确认、计数不重复，无 chat/ASR |
| 多条确认中途失败、重启 | 前一条 done 不再发送，仅继续剩余意图 |
| 最终缓存原子提交失败 | pending、旧续学文件保留；重启后可完成 |
| 原请求重复、同编号异内容 | 完成回复原样重放；异内容仍 409 |
| 旧无效 WAV | 升级结束先于格式拒绝，无新 ASR |
| 显式/可靠文字停止 | 不等待失败写入；原编号和停止编号各自可重放 |
| 删除续学文件失败 | 新开始先重试清理；包括文字 API/旧桥接；清理恢复后新课从 listen 开始 |
| 低置信度/unclear 控制词 | 不误开始，不擅自放弃 pending |
| 无 pending 的旧状态 | 正常续答进入 dialog，不强制升级结束 |

F032-1 关闭。这里采用的是可解释的跨版本安全收尾，不承诺未确认旧场景可以在新提示下无缝续答。

## F032-2：整条回答匹配仍不能凭词尾规则发明跟读成功

**位置：** `english_class/engine.py` 的 `repeats_word()` 与 `Tutor.turn()` 的 repeat 分支。

**独立复现：** 真实 Tutor 进入 zh2en，目标 apple，先答 orange 进入示范/跟读，再分别答 appled、appling。最初修复已经拒绝猜词列表，却复用了 word_forms 的无词性候选生成。两种输入均直接进入 done、写 imitated=true，并播报“这次跟读说出来了，之后再试着自己说。”此分支没有语义判题，不会由模型再过滤伪词。

**影响：** 不符合示范的错误词形被肯定和累计，与“成功模仿须有实际证据”的目标冲突。

**最终修复：** 明确跟读任务只接受规范化整条转写等于刚刚示范的词/短语，容忍大小写、空白和标点；不调用可能生成伪词的 word_forms。示范 apple 时，apples 也需要回到示范词形；若示范本身为 apples，则 APPLES! 正常接受。普通 recall/dialog 的词形与语义判断保持原合同。

**独立复验：** 重新阅读实现，运行新旧跟读、旧快照、求助支持与续学观察相关回归，**17 passed，49 deselected**。包括 appled/appling、猜词列表、示范词形不同、APPLE!、原目标 apples 及 get up 短语。失败首次重新示范，第二次仍未符合则温和继续、不记成功模仿；正确跟读仍不自动升级独立表达。F032-2 关闭。这里只核验转写是否完成该练习，不评价发音。

## F032-3：旧历史不能因为新规则更严格就被追认为成功

**位置：** `miniprogram/utils/english-view.js` 的 evidenceText；学习记录页文案；`docs/API.md` 的证据合同。

**复现依据：** v0.3.1 的 imitated_count 可以包含示范后错误使用和只含目标词的错误跟读；本版不重判或重写这些历史。将既有 imitated_count=2 交给最初修改的视图函数，却显示“累计成功跟读/模仿 2 次”。字段没有版本分段，不能据新计数规则确定两个旧事件都成功。

**影响：** 报告把无法回溯确认的旧总数描述成学习成功事实。增加“累计”只说明时间范围，未解决证据性质问题。

**最终修复及核对：** 标签改为“累计跟读/模仿记录”，继续说明“不代表独立表达”；旧数值保持。API 明确 v0.3.2 新增计数采取更严格标准，历史累计不重新判定。已重新阅读实际共享视图及两个对应页面/视图断言；主任务对最新前端运行的 63 项测试全部通过。F032-3 关闭，不需要新增字段或改写历史。

## 已独立核对的其他高风险边界

### 自带模型：实际连接地址、TLS 与代理

_resolve_llm_endpoint 把同一次 DNS 检查通过的数值 IP 返回给调用方；Providers.chat 的实际请求 URL 使用这些 IP，保留原域名 Host、sni_hostname 和正常证书校验。公开/私有地址混合答案整体拒绝，不跟随重定向。只有连接失败尝试下一个已验证地址，DNS、各次连接和响应正文共同受一个外层总时限限制。

定向回归经过真实 HTTPX/HTTPCore/AnyIO 调用链，仅在最后 TCP/测试流边界拦截：重绑定 DNS 只调用一次，TCP 只尝试已验证的 8.8.8.8，不会再解析到 127.0.0.1；覆盖域名、显式端口、IPv6、多地址继续、总时限和混合私网拒绝。TLS 流接收到原域名，SSLContext 为 check_hostname=True、CERT_REQUIRED。

另读本环境 HTTPX 0.28.1/HTTPCore 1.0.9 实际源码，确认 sni_hostname 用于 start_tls(server_hostname=...)，进一步传入 AnyIO TLS 的 hostname，不是只留在未使用的请求元数据里。没有 verify=False 或自定义跳过证书检查。自带模型 trust_env=False 阻断环境代理改道；平台模型保留原代理行为，两者有分别回归。

这些证据核验实际代码路线和校验参数，没有调用真实模型账号或互联网 TLS 端点，不是实际供应商连通性/证书端到端验收。

### 损坏录音、旧题和默认日志

当前题的新 WAV 在 recovery.begin 之前检查；损坏数据返回 422，不形成 pending、不调用 ASR、不写进度。Pi 清除无法重试的提交、保留题位并明确提示重新回答。实际 Pi route → worker → brain 回归随后发送合法 WAV，正常进入下一阶段且有效记录仅增加一次。

已完成请求的 fingerprint/缓存回放仍先行，新的旧题在 ASR 前拒绝。默认错误对象只格式化 HTTP 状态；用于恢复的 detail 保留，但不把旧题错误中完整课堂话术写入运行日志。带私有示例文本的日志捕获回归确认正文不出现在默认日志。

### 学习证据与短期上下文

代码将复制/受助与正确完成模仿分开：模型明确判错的示范后回答不记成功模仿；受助回答不升级独立掌握；正确释义但未说出目标词，会说明目标词仍需练习。逐词证据缺失/畸形时不借整体 relevant 升级，未听清也不产生一次失败观察。

answer_support 与相应学生历史行的 support 进入对话/点评；每词最新观察独立于数据库历史最高状态。观察最多对应本批 10 个词，只含原 word_id、阶段及布尔值，不另存帮助原话。旧快照显式补新字段；恢复时替换瞬态状态，不能把失败回合的观察混进旧快照。续学携带已发生的观察，真正新课清空上一课观察。

提示词接受符合任务的自然短答和合理提问，限制到一处有用的自然纠正，表扬依据实际表现，并区分有帮助和独立表达。新增文具店/午餐场景符合日常交流目标，原兴趣模板保留。这里确认约束和证据送达模型，不保证真实模型每次正确执行，也不把年级或三档历史记录解释为新的语言等级。

### 实际小程序页面的异步顺序

独立运行新增 `tests_js/v032-frontend.test.js`，**10 项通过**。测试执行真实页面 JavaScript：初始场景读取晚于保存/清除时不能恢复旧内容；生成采用带课堂身份的今日草稿年级；直接进入或读取失败时不猜成一年级；听力换年级和重新进入时先清空旧列表，加载中不能下载旧素材；记录明确历史最高与累计含义。

额外手动走通年级读取失败后的恢复：首次 gradeReady=false、错误可见、loading 结束；调用页面实际重新读取处理函数后得到 grade=8，再生成时请求确为 grade=8，旧错误消失。已读 WXML 可见/禁用条件及共享生命周期函数，确认按钮与处理函数配套，而非只测试孤立辅助函数。

页面验证使用可控 wx/Page 和音频替身，不等同于微信开发者工具、手机渲染或实际音频播放验收。
