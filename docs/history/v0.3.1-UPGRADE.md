# 从旧版升级到 v0.3.1

本包不会自动覆盖你的线上项目。旧版小程序、公共层、学生脑端和 Pi 的语音协议必须配套升级，尤其是 `/voice/audio` 新增会话与题目编号。

## 1. 先结束当前练习并备份

选择没有孩子正在练习的时间。备份 `/opt/english-class`、各学生代码和 prompts、`/etc/english-class`、Pi 插件与配置，以及脑端和 Pi 状态目录。配置和数据库中有凭证，备份只保存在老师控制的位置。

数据库使用 SQLite backup API，避免只复制正在写入的主文件而漏掉 WAL：

```bash
sudo /opt/english-class/.venv/bin/python - <<'PYBACKUP'
import sqlite3, datetime, os
path='/root/english-class-before-v031-'+datetime.datetime.now().strftime('%Y%m%d-%H%M%S')+'.sqlite3'
with sqlite3.connect('/var/lib/english-class/class.sqlite3') as source, sqlite3.connect(path) as target:
    source.backup(target)
os.chmod(path,0o600)
print(path)
PYBACKUP
```

不要将旧数据库替换为测试数据库，也不要重新创建已有学生。

## 2. 在新目录先运行测试

解压后进入 `aienglishhelper/`，安装开发依赖并运行 `scripts/test_all.sh`。查看本包 `docs/TEST_REPORT.md`。这一步不需要服务器密钥，不会碰生产数据。

## 3. 升级服务器代码和学生副本

只暂停本项目的 `english-public` 和需要更新的 `english-brain@学生ID`。保留现有 `.venv`、`students/`、配置、数据库和凭证。

对比并更新公共目录中的 `english_class/`、`prompts/`、`data/listening/`、`scripts/`、`deploy/` 和依赖文件。原词库已匹配时可保持原有数据；自改词库先保留自改版本。运行现有虚拟环境 pip 安装本包 requirements。

每个学生实际运行 `/opt/english-class/students/<sid>/english_class`。需要把本包完整 `english_class/` 和新版 `prompts/scenes.md` 合并到该副本，保留或手工合并学生对 `prompts/student.md`、引擎的个性化修改。不要仅复制一个 engine.py：新引擎依赖 scene_prompts、恢复模块与新模型定义。

重新安装匹配的 `english-public.service`、`english-brain@.service`，再 `systemctl daemon-reload`。学习数据库启动时自动追加 thinking、心跳与额度相关字段，旧进度保留；旧配置读出补 `mode=full`、`scene=null`。

## 4. 升级 Pi 与小程序

Pi 替换本包 `pi/`、`english_class/` 中其引用的共享模块及脚本，保留本人 `pi.env`、声卡配置和模型。安装新版 `english-edge.service`，它新增私有 `StateDirectory=english-class-edge` 用于未确认回合恢复。只改源码不更新服务单元，会丢失跨重启恢复能力。

微信工程使用本包完整 `miniprogram/`；保留自己的 AppID 与本人连接配置。旧两页 overlay 不再作为本版入口。正式微信后台同时配置 request 和 downloadFile 域名。

## 5. 恢复与检查

先启公共服务，确认 `/health` 为 v0.3.1，再启每学生脑端并确认版本，然后启 Pi。做一次短文字练习，核对原进度仍在；再按 INSTALL 第 8 节跑语音和手机验收。

旧状态文件不会变成永久对话档案。新版脑端恢复日志与 Pi 未确认请求最长有效 6 小时；词汇续学断点保留 7 天。明确结束后应保留已写学习进度。

## 6. 回滚

若目标环境出现新问题，先停止本版相关服务，保留当前数据用于分析，再恢复备份的代码、服务单元和与旧版本匹配的配置／数据库。因为新配置有旧版不接受的字段，不能只回滚一个 engine.py。恢复旧数据库会丢失备份之后新增记录，先由老师决定是否接受；不要直接删除现库。

原 aibot 的服务切换仍只用 `course_mode.py on/off`。升级公共层不需要停止原机器人。
